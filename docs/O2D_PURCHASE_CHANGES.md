# Purchase tab change record - 8 October 2026

## Implemented

The existing O2D material drawer now has four native calendar inputs, Purchase-only system-field protection, sheet-backed status/remarks/final dropdowns, automatic first-fill timestamps, a per-material Dispatch Order link, and an immediate row refresh after saving. Existing Close/Save buttons, drawer styling and other tabs are retained.

Purchase edits use the existing PATCH endpoint and add `context: "purchase"` and `sku`. The backend validates Enquiry No. + Sr no + SKU plus the existing id and version, then rechecks the current row, formulas, protections, timezone and dropdown settings before a narrow cell batch. Only changed editable cells and their necessary first Actual timestamps are written, with the existing audit mechanism. No whole-column writes are used. Old API request shapes remain accepted and retain their existing behavior.

Actual D, Actual G, Actual PR and Final Status Timestamp are set only when their corresponding status changes from blank to nonblank and the timestamp is empty. Existing timestamps and formulas are preserved. A protected non-formula Actual cell blocks the status change rather than saving an incomplete step. Step 9 Actual is never generated by an ordinary save or by opening the drawer.

Dates use existing `dateInputValue`/`dateSerial` helpers and true Sheet numeric dates with dd/MM/yyyy formatting. Timestamps use the spreadsheet's actual timezone. The connected workbooks report Asia/Calcutta. Blank/unedited values are preserved. Unsaved Purchase edits keep these semantics even if the user switches tabs before saving.
